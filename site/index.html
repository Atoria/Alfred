Ask your Laravel app how it works.

Alfred adds a small ? button to your app. Click it, click any number, column or badge, and get a plain-language answer traced through your own code.

composer require atoria/alfred

Questions it answers

Everyone who uses your app has questions about what's on the screen. Usually they end up in a developer's inbox. With Alfred, they ask the page.

“How is this calculated?”

Finance, operations, support

Alfred's agent reads the controller, the components, the scopes and the queries behind the value, then explains it in plain words: what it means, the formula, the steps, where the data comes from and what's worth knowing.

  • Your team can verify or edit an answer. Everyone then sees “Verified” instead of “AI-generated”.
  • The first answer takes 10 to 40 seconds. After that it's saved and instant for everyone.
“Does that include refunded orders?”

Anyone reading the answer

Ask a follow-up right under the explanation. Alfred goes back to the code for the specifics. Your questions stay private to you, and a reviewer can add a good answer to the explanation for everyone.

“Which orders make up this number?”

Anyone checking a figure

“Show the records behind this” turns a count or a sum into the rows it was calculated from. Columns you mark as sensitive stay hidden.

“Where does this live in the code?”

Developers, and new joiners most of all

The developer tab shows the code path: each file and line on the way to the value, the queries it runs, how it's cached and the traps. It's only shown to people who are allowed to see code.

“Can we make this green when it's above 2.5%?”

Product, design, QA

Describe a change in your own words. Alfred finds the code and proposes the smallest edit that does it, shown as a diff. Nothing is written until someone decides to.

  • Not quite right? Refine it, and Alfred tries again knowing what was wrong.
  • It works with Blade, Livewire and Filament, and with Vue, React and Svelte through Inertia.
“What would that look like?”

Whoever asked for the change

Preview the change on the real page, with real data. Only you see it, and the code isn't touched. From the preview bar you can open a pull request or a ticket, refine the change, or stop.

“Can someone pick this up?”

The person who found it

Turn a change or a plain report into a ticket in your tracker. It comes with the request, the diff, screenshots and where the element lives in the code, and optionally with a draft pull request linked both ways.

“Can a developer review the code first?”

Teams that ship through pull requests

Open a draft pull request straight from the change or the preview bar. Alfred commits the edit to a new branch through GitHub, GitLab or Bitbucket and opens the request for review. Git isn't needed on the server, so it works on staging and hosted platforms too.

  • Create the ticket and the pull request together, linked both ways.
  • Prefer to apply it yourself? Download the patch and run git apply.
“This number looks wrong.”

Anyone, no AI needed

Report a problem or ask for something in your own words. Alfred turns it into a ticket with a screenshot of the element and where it lives in the code: the route, the controller, the views and the components. If you asked about it first, the explanation and your questions go along too.

Who it's for

People who rely on the numbers

Operations, finance and support get answers on the spot, from the code that actually produces the figure. Reviewed answers show as verified.

People who shape the product

Product managers, designers and testers on staging can describe a change, see it on the page and hand it over as a ticket or pull request, without waiting for a developer to find the file.

Developers

Fewer “how is this worked out?” messages. Tickets arrive with the diff and the file. Locally, you can apply a change and undo it in one click.

Works with what you have

Laravel
Laravel 11, 12 and 13 on PHP 8.2 or newer. No annotations in your views.
Front end
Blade, Livewire, Filament, and Inertia with Vue, React or Svelte.
AI models
OpenAI built in. Claude, Gemini, Groq, Ollama, OpenRouter and more through LarAgent, with fallbacks, usage tracking and optional daily budgets.
Ticket trackers
Jira, GitHub Issues, GitLab, Linear, Trello, ClickUp and Asana, or your own. Without a tracker, copy the ticket as Markdown.
Pull requests
Draft pull requests on GitHub, GitLab or Bitbucket, made through their APIs. Git isn't needed on the server.
Multi-tenant apps
stancl/tenancy and spatie/laravel-multitenancy. Every explanation, change and ticket stays in its tenant.
Command line
php artisan alfred:doctor checks your setup without printing secrets. php artisan alfred:usage shows what the AI used, by day, person or kind.
Testers on staging
Visitors who aren't signed in can use Alfred on staging through a private access link, with their own rate limits. Never in production by default.

Stays out of the way

  • Put the panel side by side with the page, so it covers nothing.
  • Drag its edge to resize it, or move it to the other side.
  • Minimize it while it works. A small button tells you when it's done.
  • Your name, icon and colour, light and dark mode, and a shadow root so your CSS and Alfred's never clash.

And the rest of the workflow

Careful with your code and your data

Hidden until you choose

Nobody sees Alfred until you list them by email or give them a gate. Everyone else gets no button and no script.

Reads only what you allow

The agent reads the folders you list. It never reads .env, keys, credentials, storage, vendor or .git, and it can't change providers, policies or middleware.

Nothing written unless you say so

Propose mode never writes on the server. Previews exist only in your own session. Apply and undo refuse if the file has changed since.

Your data stays on your server

By default the AI sees your code, never the values on the page. Anything that looks like a credential is removed first. Daily budgets cap what it can spend.

Set it up in four lines

Install, migrate, add your key and say who may use it. Sign in, reload, and the ? appears in the corner.

Every option is in the configuration reference. To check your setup, run php artisan alfred:doctor.

composer require atoria/alfred
php artisan migrate

# .env
ALFRED_ENABLED=true
ALFRED_OPENAI_API_KEY=sk-...
ALFRED_USERS=*@your-company.com
ALFRED_VERIFIERS=you@your-company.com
